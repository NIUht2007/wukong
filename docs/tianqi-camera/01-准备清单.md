# 甜气相机 · 开工前准备清单

> 目标：用 Kimi Code 开发 **Android 单端** App。在敲下第一句提示词之前，把下面 4 类事项准备好。

---

## 一、技术决策（开工前拍板，各选其一即可）

| 决策项 | 推荐方案 | 备选 | 说明 |
|---|---|---|---|
| 技术栈 | **Flutter（仅 Android 构建）** | Kotlin + Jetpack Compose（原生） | 即使只做安卓也推荐 Flutter：Skia 自绘引擎做拼图画布、涂鸦、贴纸合成非常顺手，插件生态成熟（camera、image、photo_manager），且未来若想扩 iOS 几乎零成本；原生 Kotlin 性能上限更高但开发慢、只能跑安卓 |
| 美颜方案 | 一期自研基础版（磨皮=表面模糊、美白=曲线提亮、瘦脸大眼=网格液化） | 商用 SDK（相芯 FaceUnity、商汤、字节效果 SDK） | 商用 SDK 效果专业但要申请商务授权且收费；一期让 Kimi Code 用图像算法实现基础版，验证产品后再换 |
| 图像保存/分享 | 系统相册 + 系统分享面板 | 接入微信/QQ 分享 SDK | 一期用系统能力，零成本；后期再接入平台 SDK |
| 数据存储 | 纯本地（相册 + 本地草稿箱） | 云端账号体系 | 一期不做账号，全部本地处理，还规避大量隐私合规成本 |
| 后端服务 | **一期不需要** | 模板/贴纸云端下发 | 模板和贴纸包先内置在 App 里 |

**建议：直接把"Flutter + 本地存储 + 无后端"写进给 Kimi Code 的第一条提示词，避免它自己替你选。**

---

## 二、开发环境（你电脑上要装的东西）

> 好消息：这些环境搭建本身也可以让 Kimi Code 给你生成 step-by-step 命令。

- [ ] **Flutter SDK**（最新 stable 版）+ Dart（随 Flutter 自带）
- [ ] **Android Studio**（Android SDK、模拟器）—— Windows 或 Mac 均可，无系统限制
- [ ] **Android 真机一台**（建议中端机型，如 Redmi / 小米数字系列），相机类 App 模拟器测不出真实效果
- [ ] Git（Kimi Code 生成的代码用 Git 管版本，出错随时回滚）

验证环境是否就绪：终端执行 `flutter doctor`，全部打勾即可。

## 三、账号与合规（上架前必须，建议尽早办，有的周期长）

| 事项 | 费用/周期 | 备注 |
|---|---|---|
| 国内安卓应用商店开发者账号（华为/小米/OPPO/vivo/应用宝） | 免费，但需要**软件著作权** | 软著申请周期 1-2 个月，建议开工就同步去办；各商店还要求企业或个体户资质（个人开发者部分商店受限） |
| **隐私政策 + 用户协议** | — | 相机/相册类 App 上架强制要求；可让 Kimi Code 先起草模板，再找律师过一遍 |
| App 名称查重 + 商标检索 | — | 确定「甜气相机」没被占用（各安卓商店、商标局网站各查一遍） |
| Google Play 开发者账号 | $25 一次性 | **可选**，只打算发国内就先不办 |

## 四、产品素材（Kimi Code 写代码时需要引用的资源）

开工前准备好，放进项目的 `assets/` 目录：

- [ ] **App 图标**：1024×1024 PNG（圆角由系统处理，给方形图）
- [ ] **启动页图**：一张甜系品牌图
- [ ] **贴纸包**：20-30 张 PNG 透明底贴纸（蝴蝶结、腮红、星星、手绘线条等甜系元素），单张建议 512×512
- [ ] **字体**：1-2 款免费可商用的圆体/手写体（如站酷快乐体、思源圆体），注意下载授权文件并存档
- [ ] **拼图模板定义**：可以先用 JSON 描述（见提示词文件，Kimi Code 会帮你设计结构）
- [ ] **示例照片**：5-10 张测试图（人像、食物、宠物、风景各几张，用于调滤镜）

素材去哪找、授权注意什么 → 见 `04-素材与设计规范.md`

## 五、Kimi Code 协作小贴士（写给第一次用的人）

1. **先喂上下文，再下任务**：把 `02-PRD` 和 `04-设计规范` 全文贴给它（或放进项目目录让它读），再用 `03-提示词` 里的分阶段指令逐步推进。
2. **一次只让它做一个功能**，跑通验收后再给下一个提示词，不要一口气"帮我把整个 App 写完"。
3. **每个阶段结束就 `git commit`**，Kimi Code 改崩了随时回滚。
4. **报错就原样贴回去**（完整错误日志 + 让它自查），它自己修 bug 的效率很高。
5. 涉及真机调试的问题（相机权限、相册读写），明确告诉它你的手机型号和系统版本。
